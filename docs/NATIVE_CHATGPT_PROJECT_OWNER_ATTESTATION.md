# Native ChatGPT Project Evidence — Owner-Attested Browser Upload

## Purpose and current boundary

Every required Game Factory artifact needs a verified immutable primary object, a byte-verified Google Drive copy, and native ChatGPT Project evidence. A documented native Project verification API is the preferred evidence path. It is not currently available to this runtime.

The owner has approved one narrow temporary fallback: an offline privileged operator may append an `OWNER_ATTESTED` record after the owner visibly confirms an exact browser file upload in the locked native Project:

`g-p-6a97fd4de8ac8191ae375fe1242c1ea8`

`OWNER_ATTESTED` is not labelled machine-verified. It satisfies the native Project portion of mandatory-artifact completion only under this approved rule. It does not enable release writes, signing, store uploads, Android, iOS, or any worker capability.

Until a record is actually appended for every current artifact version, the normal Start path remains partial and returns `503 mandatory_artifact_copies_incomplete`. This procedure does not create evidence for the current production artifacts by itself.

## Hard boundaries

- The native API, once documented and independently verified, is preferred over this fallback.
- Only the exact locked Project ID above is accepted.
- Only **Fred Wolfe**, the named project owner, may make the owner attestation.
- The upload must use the native ChatGPT Project browser **file-upload** control. Textarea/pasted content is rejected.
- The Project browser source list must visibly show exactly one source with the canonical filename. A screenshot alone is not evidence.
- A Drive URL/link, local-file observation, generic browser observation, worker result, HTTP request, public UI action, or undocumented ChatGPT API cannot create or update native evidence.
- The command has no network, browser automation, Drive, worker, or HTTP behavior. It does not upload anything; it records a post-upload owner attestation only.
- The ledger is append-only. Records cannot be edited, relabelled, or deleted. A later source removal or ambiguity is recorded as a new invalidation event, which de-completes the artifact.

## Preconditions

Before preparing a manifest, confirm all of the following from the durable artifact ledger:

1. The selected artifact is its **current** version for the artifact key.
2. The local primary copy is `VERIFIED` with the exact registered SHA-256.
3. The Google Drive copy is `VERIFIED` with the same SHA-256.
4. The owner has uploaded the exact immutable artifact bytes through the native Project browser control and can visibly see the source in the locked Project’s source list.
5. The server process using this Game Factory SQLite database is stopped. The command is intentionally an offline, single-writer maintenance action.

The canonical filename is:

`<artifact-key-lowercase>__v<version>__<artifact-id-lowercase>__<first-20-sha256-hex>.<extension>`

For a Markdown artifact, the extension is `md`. The values must exactly match the current artifact record; the command recomputes and checks the filename rather than trusting the manifest.

## Attestation manifest

Create a regular JSON file on the privileged operator machine. Do not use stdin, a browser textarea, or a Drive link. The command reads only a regular, non-symlink JSON file no larger than 64 KiB.

```json
{
  "formatVersion": 1,
  "kind": "OWNER_ATTESTED",
  "nativeProjectId": "g-p-6a97fd4de8ac8191ae375fe1242c1ea8",
  "artifactId": "gfa_<current-id>",
  "artifactKey": "00_GAME_BRIEF",
  "artifactVersion": 1,
  "sha256": "<64-lowercase-hex>",
  "size": 1234,
  "filename": "00_game_brief__v1__gfa_<current-id>__<first-20-sha>.md",
  "sourceCount": 1,
  "operator": "Fred Wolfe",
  "observedAt": "2026-09-02T12:00:00.000Z",
  "browserEvidenceRef": "chatgpt-project-browser://g-p-6a97fd4de8ac8191ae375fe1242c1ea8/visible/<opaque-owner-reference>",
  "uploadMethod": "BROWSER_FILE_UPLOAD",
  "evidenceOrigin": "OWNER_CONTROLLED_CHATGPT_PROJECT_BROWSER",
  "sourceListVisible": true,
  "screenshotOnly": false,
  "ownerAttestation": "I directly verified in the owner-controlled native ChatGPT Project browser UI that exactly one file was uploaded with this exact filename to the locked Project."
}
```

The durable record calculates and stores a canonical SHA-256 `manifestHash`; it never trusts a caller-provided hash. It also rechecks artifact ID/key/version, hash, byte size, canonical filename, locked Project ID, operator, visible source count, and both primary and Drive verification before inserting anything. The observation must not predate the artifact, may be no more than five minutes ahead of the command clock for bounded clock skew, and must be strictly newer than every earlier attestation or invalidation for that artifact.

`browserEvidenceRef` is an opaque owner-browser reference, not an API locator or proof generated by an undocumented endpoint. It must use the exact `chatgpt-project-browser://<locked-project-id>/...` shape and cannot be a Drive, HTTP, file, screenshot, or local path reference.

## Offline record command

Run only after the browser upload is visibly confirmed and the application service is offline:

```text
node ops/record-native-chatgpt-project-attestation.mjs attest \
  --offline --commit \
  --data-dir <absolute-game-factory-data-dir> \
  --uid <owner-uid> \
  --game-id <game-id> \
  --artifact-id <current-artifact-id> \
  --manifest <absolute-owner-attestation.json>
```

The command never defaults `DATA_DIR`, does not accept pasted JSON, and emits only a bounded receipt: status, ledger ID, status label, and manifest hash. It opens the non-symlink regular manifest once, validates the opened file identity, and parses only the bytes read through that same descriptor. A repeated identical manifest is idempotent. A different active attestation is rejected as ambiguous until the prior evidence is invalidated.

## Invalidation after removal or ambiguity

If the owner later sees that the source disappeared, more than one matching source exists, the Project is wrong, or the upload method was invalid, append an invalidation—never edit the old record. The invalidation manifest has `kind: "INVALIDATED"`, the original evidence ID, the locked Project ID, Fred Wolfe as operator, an ISO timestamp, a permitted reason (`SOURCE_REMOVED`, `SOURCE_AMBIGUOUS`, `PROJECT_MISMATCH`, or `UPLOAD_METHOD_INVALID`), the observed source count, and a fresh opaque browser evidence reference.

```text
node ops/record-native-chatgpt-project-attestation.mjs invalidate \
  --offline --commit \
  --data-dir <absolute-game-factory-data-dir> \
  --uid <owner-uid> \
  --game-id <game-id> \
  --artifact-id <current-artifact-id> \
  --manifest <absolute-invalidation.json>
```

An invalidation makes the native backend `INVALIDATED` and immediately returns the artifact to incomplete status. Re-attestation requires a new visible upload confirmation and a new manifest; it never changes old evidence.

## Future native API path

Do not add an undocumented internal ChatGPT API adapter. When a documented native Project verification API becomes available, it needs a separate reviewed adapter that produces `NATIVE_API_VERIFIED` evidence bound to the same immutable fields. The current code intentionally exposes no generic API writer and no HTTP path for that future status.

## Project-artifact mirror requirement

This operator document changes project operating knowledge. Before it is treated as a complete project-artifact update, mirror the exact reviewed bytes to the required Google Drive project location and record a genuine native Project copy through the process above. This implementation pass made no Drive or native Project production write.
